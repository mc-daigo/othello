以下の質問について順番に解説します。

1. 「全部コミットしないとブランチBに切り替えられない場合があるのはなぜか？」
これは、Gitが作業中の変更（作業ディレクトリやステージングエリアの状態）を他のブランチに持ち越せるか判断するためです。

原因
競合する変更がある場合:
現在のブランチの変更内容が未コミットで、切り替え先のブランチの内容と競合する場合、Gitはブランチを切り替えることをブロックします。
この競合を避けるために、作業中の変更をコミットするか、スタッシュする必要があります。
解決方法
作業をコミットせずにブランチを切り替えたい場合: 作業中の変更を一時保存（スタッシュ）すれば、ブランチを切り替えられます。
bash
コードをコピーする
git stash
git checkout B
git stash apply
2. 「Bに切り替わってもファイルDは元に戻っていないか？」
Gitの動作
ファイルDがブランチAに未コミットの場合:
作業ディレクトリにある変更（未コミットの状態）は、ブランチを切り替えてもそのまま残ります。
ただし、切り替え先のブランチ（B）にファイルDの別のバージョンが存在していた場合、競合が発生する可能性があります。
結論
ファイルDは、未コミットのままブランチを切り替えた場合、そのまま保持されます。
ただし、競合がないことが前提です。
3. 「git addしたら修正後に戻るか？」
git addの動作
git addを実行すると、作業ディレクトリの変更がステージングエリアに追加されます。
その後、作業ディレクトリ自体は修正後の状態を維持します。git addがファイルの状態を「元に戻す」ことはありません。
状況別の挙動をまとめる
状況	挙動
未コミットの変更がある場合	競合がなければそのままブランチを切り替えられ、変更内容も保持される。
切り替え先に競合する変更がある場合	切り替えを拒否され、変更をコミットまたはスタッシュするよう求められる。
git addを実行した場合	作業ディレクトリの内容は修正後の状態を維持。ステージングエリアに変更が登録されるだけ。
スタッシュしてから切り替える場合	一時保存されるため、競合の心配なくブランチを切り替えられる。git stash applyで復元可能。
結論
未コミットの変更がある場合、競合がなければブランチを切り替えても変更は保持されます。
競合がある場合、Gitはブランチの切り替えをブロックします。解決策としてコミットまたはスタッシュが必要です。
git addはファイルの状態を保持したまま、変更をステージングエリアに登録するだけです。修正内容は元に戻りません。

Gitスタッシュの詳しい解説
Gitの**スタッシュ（stash）**機能は、現在の作業内容（未コミットの変更）を一時的に保管し、クリーンな状態で別の作業を行えるようにするものです。その後、必要なタイミングで保管していた内容を復元できます。

スタッシュの基本的な流れ
現在の変更をスタッシュする（保管）
作業ディレクトリやステージングエリアの変更を一時的に保存します。
別のブランチに移動
クリーンな状態でブランチを切り替えたり、新しい作業を行います。
スタッシュを復元
保管していた変更内容を元に戻します。
具体的な手順とコマンド
1. 現在の作業をスタッシュする
bash
コードをコピーする
git stash
作業ディレクトリの変更とステージングエリアの変更が、スタッシュに保存されます。
作業ディレクトリとステージングエリアはクリーンな状態に戻ります。
例:

作業ディレクトリにファイルAとファイルBを修正したが、コミットしたくない場合：
bash
コードをコピーする
git stash
2. ブランチを切り替える
スタッシュした後は、自由にブランチを切り替えられます。
bash
コードをコピーする
git checkout <別のブランチ名>
3. スタッシュを復元する
元のブランチに戻ってスタッシュを復元します。
bash
コードをコピーする
git stash apply
作業ディレクトリとステージングエリアが、スタッシュしたときの状態に復元されます。
スタッシュに関する追加のコマンド
スタッシュ内容を確認する
bash
コードをコピーする

スタッシュに保存されている作業内容のリストを表示します。
例:

特定のスタッシュを復元する
スタッシュリストから特定のスタッシュを復元したい場合：
bash
コードをコピーする
git stash apply stash@{1}
スタッシュを削除する
スタッシュを復元した後や不要になった場合、削除することでスタッシュのリストを整理できます。
bash
コードをコピーする
git stash drop stash@{0}
すべてのスタッシュを削除したい場合：
bash
コードをコピーする
git stash clear
スタッシュを使った具体的な例
シチュエーション
ブランチAでファイルCとファイルDを修正している。
ファイルCはコミットするが、ファイルDは保留したい。
別のブランチBに移動して作業を進め、後で保留していたファイルDの作業を復帰させたい。
手順
ファイルDをスタッシュに保存する

bash
コードをコピーする
git stash
これでファイルDの変更がスタッシュに保管され、作業ディレクトリがクリーンな状態に戻ります。
ファイルCをコミットする

bash
コードをコピーする
git add ファイルC
git commit -m "Update ファイルC"
別のブランチBに移動して作業を行う

bash
コードをコピーする
git checkout B
元のブランチAに戻ってスタッシュを復元する

bash
コードをコピーする
git checkout A
git stash apply
スタッシュした内容をコミットする

スタッシュ復元後にファイルDをコミットします。
bash
コードをコピーする
git add ファイルD
git commit -m "Update ファイルD"
注意点
スタッシュは一時保存:

スタッシュは一時的な保存場所です。変更を復元後、コミットするか削除することを忘れないでください。
競合の可能性:

スタッシュを復元したとき、他の変更と競合が発生する場合があります。この場合、競合を解決する必要があります。
まとめ
スタッシュは、未コミットの変更を一時保存する便利な機能。
作業を中断して別の作業を進めたいときに有用。
スタッシュから復元後はコミットすることで、履歴に記録できます。
疑問があればさらに詳しく説明します！
